Fixed; the grid now uses four columns up to 640 px and columns that can shrink. - Results of the run: 300 of 300 resolved, 87 flagged, 0 flags without a CDC quote, 0 stop instructions, agreement 75.0% with UKHSA and 82.3% with Health Canada, 18 flags outside both keys, 128 disagreements each with a reason.
- Final review found that a Honolulu ZIP showed the Phoenix 2025 heat wave as "saved data" with "Wed is an Extreme heat risk day where you live". Root cause: the HeatRisk service answers points outside the contiguous US with an ArcGIS error body (code 400, "Invalid or missing input parameters") under HTTP 200, and the client treated every error as an outage. The spec assumed out-of-area points would return empty or NoData samples. Fixed with a contiguous-US bounds check before any call plus code-400 handling, and the summary now uses past-heat-wave wording whenever boxes show saved data.
- While fixing it, a new guard test showed two "never say today" regexes were vacuous: the shell tool collapses doubled backslashes, so regex escapes written through a Python heredoc became invisible backspace characters. Fixed with byte-level replacement through a script written by the file tool, a repo-wide scan (49 files, no other control bytes), and a test that proves the pattern matches what it guards against.
