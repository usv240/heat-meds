The Phoenix example through the system

Step through what happens, in order, when the daughter types Lasix and 85001.

1. "Lasix" becomes furosemide

What happens

  • normalizeName("Lasix 40 mg") strips dose and form words → "lasix". Exact search fails on "Toprol XL" and "lasix 40 mg" without this.
  • rxnorm.js calls rxcui.json?name=lasix&search=2 and gets an RxCUI.
  • rxcui/{id}/properties.json says it's a brand (BN), so the module asks related.json?tty=IN and gets furosemide.
  • A plain ingredient input (tty IN or PIN) stops here and never follows related combination products. A PIN like metoprolol succinate also records its base ingredient for name rules.
  • No exact match → approximateTerm.json; the top candidate becomes a "Did you mean metoprolol (Toprol XL)?" chip that needs one tap. Scores are unreliable, so nothing approximate is accepted silently.
  • No candidate → spellingsuggestions.json; still nothing → "not recognized."
  • The list is written to localStorage.

2. Furosemide gets its ATC codes

What happens

  • rxclass.js calls rxclass/class/byRxcui.json?rxcui=…&relaSource=ATC.
  • Keeps only rows where minConcept.rxcui is furosemide itself. Rows for combination products that contain furosemide (the C03CB leak the learner found) are dropped.
  • Result: C03CA, loop diuretics. RxClass returns ATC level 4, verified by the learner.

3. 85001 becomes coordinates, then 7 heat levels

What happens

  • zip.js fetches data/zip/850.json, a slice of the Census ZCTA gazetteer, and finds Phoenix.
  • heatrisk.js calls the ImageServer getSamples at that point and gets one sample per day layer: value is a string ("1"), idp_validtime is epoch milliseconds. Verified by the learner.
  • Empty or NoData → "forecast not available for this ZIP." Any failure → the saved Phoenix heat wave, labeled "saved data."
  • No ZIP typed → "Add a ZIP code to see this week's heat where you live."

4. The rules engine builds the plan

What happens

  • rules.js deduplicates ingredients by RxCUI, matches ATC prefixes and ingredient names against cdc-rules.json.
  • Cards for furosemide and lisinopril; one combination warning (diuretic + ACE inhibitor), once, even if a combo pill and a separate water pill both appear.
  • Insulin → storage note. Atorvastatin → "Not listed in CDC heat guidance" with UKHSA and Health Canada badges.
  • Forecast touches only this_week_days (level 2 or higher) and the summary. Card text never changes.
  • plan-render.js draws it; info.js attaches an "i" to every term and number.

What happens

Stack and where it runs

Stack

  • HTML, CSS, JavaScript ES modules. No bundler, no framework, no runtime dependencies.
  • Node 20+ for scripts and tests, built-in node:test and fetch.
  • One dev dependency, geotiff, for the one-time heat wave sampling script.
  • Font: Atkinson Hyperlegible Next, OFL, self-hosted from the Google Fonts repo. 20 px base.

Run, test, deploy

  • Local: npx serve . or python -m http.server 8000, open http://localhost:8000/. Modules need HTTP, not file://.
  • Tests: node --test. Proof: node scripts/run-evidence.mjs (minutes; throttled and cached).
  • Deploy: GitHub Pages, main branch root, with .nojekyll.
  • Submission: public repo + short demo video required; the Pages URL is extra.

PRD: The CDC rules file (as product content)

Rules engine shared with tests src/rules.js
evaluate({ medicines, forecast, rules }) → {
  summary: { level_max, red_or_worse_days, text },
  week: [{ date, level, word }] | null,
  cards: [{ ingredient, as_typed, class, why, watch_for, ask, this_week_days, source }],
  combinations: [{ text, source }],        // deduplicated by rule id
  storage: [{ ingredient, text, source }],
  not_listed: [{ ingredient, as_typed, badges: { ukhsa, health_canada } }],
  unrecognized: [as_typed]
}

Pure, no network. Deduplicates by RxCUI. A combination pill hitting both classes triggers the combination alone. Forecast affects only this_week_days (level 2+) and summary. Badges come from the answer-key files.

Evidence page and proof pipeline proof evidence.html · src/evidence.js · scripts/ · data/answer-keys/
  • Top 300 from AHRQ MEPS HC-254A (2024 Prescribed Medicines, public domain): group fills by drug name, sum person weight, normalize to RxNorm ingredients crediting combination fills to each ingredient. Top-20 sanity check against published rankings, comparison only.
  • Answer keys UKHSA (OGL) and Health Canada 2024 pharmacist guidance, scored. ANSM context only. Phrase → ATC prefixes or ingredients with a one-line reason; narrower reading when ambiguous; committed before the run.

  • Page renders the JSON in fixed order plus the mapping table and the limitation sentence.

Failure modes and simplifications

Where it will break

  • HeatRisk fails or moves → saved Phoenix heat wave, labeled. Fallback exercised by a test with fetch stubbed to fail.
  • RxNorm slow or down → "couldn't check right now, try again"; saved lookups for the example and the 300.
  • ZIP missing or outside CONUS → note in the heat area; cards still render.
  • Rate limit during the run → throttle, retry once, cache.

What was simplified

  • Three static pages, no bundler, no framework.
  • Bundled ZIP slices instead of a geocoding service.
  • One saved heat wave instead of an archive browser.
  • Committed evidence.json; CI later.
  • ANSM shown, not scored.
  • Single-ingredient inputs never expand to combination products.

Decisions and open issues

The useful unknown

Mapping UKHSA's broad phrases to ATC codes decides the agreement numbers and could be tuned to flatter the app. The learner's check: write both mappings with a reason per phrase and commit them before the run; take the narrower reading of anything ambiguous; show the mapping table on the Evidence page. Evidence: the answer-key commit precedes the first evidence.json commit.

Second: MEPS name normalization. Count by ingredient, credit combination fills to each ingredient, sanity-check the top 20 against published rankings (comparison only). Evidence: a note in top300.json.

Learner decisions
  • Plain HTML/CSS/JS ES modules; Node node:test. Same rules module in site and test.
  • HeatRisk via ImageServer getSamples from the browser, verified Sept 29, 2026; saved-data fallback; verification is build step one.
  • Past heat wave: Phoenix Aug 3 to 9, 2025, from archive Day-1 GeoTIFFs, committed with sources.
  • ZIP from a bundled Census gazetteer split by first three digits. No third service.
  • Top 300 from MEPS, not ClinCalc (license). By ingredient.
  • UKHSA and Health Canada scored; ANSM context only. False alarm = flagged by app, listed by none of the three.
  • "Not listed in CDC heat guidance" with UK and Canada badges replaces "no known heat concern."
  • RxClass filter to the ingredient's own RxCUI; split ingredients only for combination inputs.
  • Atkinson Hyperlegible Next from the Google Fonts repo, self-hosted, 20 px base.
  • Commit the generated evidence file; GitHub Action later.
  • Name lookup never guesses silently: strip dose and form words; approximate matches become a one-tap "Did you mean ...?" chip.
  • "Flags without a CDC quote" (must be 0, enforced in code) replaces the partly circular "false alarms." Flags among medicines neither UKHSA nor Health Canada lists are reported with their quotes.
  • CDC list curated line by line; acetaminophen, levothyroxine, indinavir are "confirm or drop"; laxatives, opiates, benzodiazepines, apixaban, antacids, sun-sensitizing drugs are "confirm."
  • MIT LICENSE file. No em dashes in site text, devpost docs, or README.

Open issues for the build

  • Step one: live smoke check of getSamples from the browser at the Phoenix point. Shape already known; this is confirmation because the service is experimental.
  • MEPS HC-254A download format; adapt the reader.
  • Exact HeatRisk hex colors from the WPC legend; NoData outside CONUS (archive rasters use 5; confirm live).
  • Exact UKHSA and Health Canada URLs and license text for References.
  • The CDC classes, quotes, and storage items are curated first, per the agreed build order.
  • Resolved before approval: RxClass returns ATC level 4; getSamples values are strings with epoch-ms times; archive GeoTIFFs are Web Mercator (pixel 2539.703 m, origin -14326021.825, 6722143.668, NoData 5) and sample correctly.
